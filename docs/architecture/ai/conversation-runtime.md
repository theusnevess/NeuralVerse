# Conversation Runtime Architecture

## Overview

The Conversation Runtime manages conversation state for NeuralVerse AI Copilot. It sits between the UI and the LLM Runtime, handling:

- Conversation lifecycle (create, pause, restore, finish, archive)
- Message history (append, query, order)
- Context synchronization (route, lesson, module, path)
- Memory management (artifacts, quizzes, diagrams)
- Summary generation (deterministic, from messages)
- Persistence (in-memory, localStorage, future backend)

**Core Principle:** Conversation belongs to NeuralVerse. Generation belongs to the LLM.

## Architecture

```
UI Copilot
    ↓
Conversation Manager ← THIS LAYER
    ↓
Copilot Runtime
    ↓
Prompt Compiler
    ↓
LLM Provider
    ↓
Response Validator
    ↓
Response Renderer
```

## Conversation States

| State | Description |
|-------|-------------|
| `new` | Just created, no messages |
| `active` | Has messages, user is interacting |
| `paused` | Temporarily suspended |
| `restored` | Resumed from persistence |
| `finished` | Conversation completed |
| `archived` | Stored for historical reference |

## Message Types

| Type | Source | Purpose |
|------|--------|---------|
| `user` | User input | Questions and commands |
| `assistant` | LLM response | Generated answers |
| `system` | System | Instructions and context |
| `context` | Navigation | Current lesson/path info |
| `guardrail` | Governance | Policy notices |
| `developer` | Dev mode | Technical metadata |
| `tool` | Tools | External tool outputs |
| `artifact` | Generation | Quizzes, diagrams, etc. |

## Context Synchronization

Every request automatically updates:

- Current route (where user is in the app)
- Current lesson (path > module > lesson)
- Current module
- Current path
- Current laboratory/assessment/research
- Bookmarks and notes
- Retrieval context
- Shared knowledge

Context is deterministic — extracted from navigation, not generated.

## Memory

Memory stores conversation artifacts:

- Important user questions
- Generated summaries
- Generated quizzes
- Generated laboratories
- Generated diagrams
- Generated comparisons
- Generated explanations
- References created
- Artifacts produced

Memory is extracted from messages, not generated by LLM.

## Summary

Summary is generated deterministically from messages:

1. Extract topic from first user message
2. Count messages by type
3. Extract artifact types
4. Calculate duration
5. Join into rolling summary

Summary will later be injected into prompts for context.

## Persistence

Three persistence backends:

| Backend | Use Case | Storage |
|---------|----------|---------|
| InMemoryPersistence | Tests, development | RAM |
| LocalStoragePersistence | Browser sessions | localStorage |
| Future backend | Production | Server database |

All backends implement the `ConversationPersistence` interface.

## Session Recovery

When reopening NeuralVerse AI:

1. Check localStorage for active session
2. Restore session with `restored` state
3. Restore mode, style, context
4. Show messages in chronological order
5. Preserve scroll position

## Developer Mode

Displays:

- Session ID
- Session state
- Message count
- Summary size
- Provider and model
- Selected mode
- Current route

## Runtime Restrictions

The conversation layer must NOT:

- Call LLM directly
- Call D1-D10 agents directly
- Render HTML
- Perform UI manipulation
- Perform network requests
- Contain prompts
- Contain provider logic
- Contain response generation

## Integration

### With CopilotRuntime

```typescript
const manager = new ConversationManager();
manager.startNewSession('teaching', 'simple');

// User asks question
manager.appendUserMessage('Explain neural networks');

// CopilotRuntime generates response
const response = await runtime.processRequest({
  query: 'Explain neural networks',
  mode: 'teaching',
  style: 'simple',
  currentRoute: '/learning'
});

// Store response in conversation
manager.appendAssistantMessage(response.content, {
  provider: response.metadata.provider,
  model: response.metadata.model
});
```

### With PromptCompiler

```typescript
const context: PromptCompilationContext = {
  userQuery: lastUserMessage.content,
  conversationSummary: manager.getSummary(),
  conversationHistory: manager.getMessages().slice(-10),
  // ... other context
};
```

## Future Backend Support

To add backend persistence:

1. Implement `ConversationPersistence` interface
2. Use HTTP/WebSocket for communication
3. Handle offline/online sync
4. Implement conflict resolution
5. Add encryption for sensitive data
