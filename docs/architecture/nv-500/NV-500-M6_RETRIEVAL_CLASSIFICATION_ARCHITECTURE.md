# Retrieval Classification Architecture (NV-500-M6)

## 1. Classification Evaluation & Decision
We evaluated whether a single classification model could define retrieval boundaries across all structures.

*   **Hypothesis NV500-H6:** *A single canonical classification is sufficient for all retrieval responsibilities.*
*   **Result:** **ACCEPTED**
*   **Decision:** `Canonical Retrieval Classification APPROVED`

---

## 2. Approved Classification Model
Retrieval artifacts are grouped into four unified classification classes:

1.  **Retrieval Identity:** Locks who/what the reference is canonically.
2.  **Retrieval Access:** Rules defining how/where to locate the reference.
3.  **Retrieval Relationship:** Descriptions of connections and link directions.
4.  **Retrieval Synthesis:** Methods and scopes of evidence compilation.

---

## 3. Structure Classification Mapping
The approved retrieval structures map directly to the classification classes:

*   `Reference Registry` ➔ **Retrieval Identity**
*   `Retrieval Index` ➔ **Retrieval Access**
*   `Relationship Graph` ➔ **Retrieval Relationship**
*   `Evidence Compiler` ➔ **Retrieval Synthesis**

---

## 4. Boundary Integrity Check
> [!IMPORTANT]
> **This classification model preserves the boundary of the Retrieval Governance Authority.**
>
> It does **NOT** absorb, replace, or conflict with:
> *   `Knowledge Governance` (domains)
> *   `Research Governance` (projects)
> *   `Learning Governance` (progress paths)
> *   `Content Governance` (modules/items)
> *   `Workspace Governance` (UI state)
