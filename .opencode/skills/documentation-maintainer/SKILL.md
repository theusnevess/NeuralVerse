# Documentation Maintainer Skill

Use this skill when technical decisions, architecture, setup, or workflows change.

Rules:
- Keep documentation factual and concise.
- Do not duplicate existing docs.
- Update docs only when changes are meaningful.
- Preserve canonical terminology.
- Prefer short architecture notes over verbose essays.
- Do not claim features exist unless implemented.
- Do not document speculative plans as completed work.

Useful outputs:
- ADRs
- implementation notes
- setup instructions
- testing notes
- architecture summaries
- known limitations
