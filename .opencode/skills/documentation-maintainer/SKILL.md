# Documentation Maintainer

## Purpose

Keep NeuralVerse documentation accurate, concise, and aligned with implemented behavior and durable decisions.

## When To Use

Use when technical decisions, architecture, setup, workflows, validation guidance, or harness behavior change.

## Core Rules

- Keep documentation factual and concise.
- Do not duplicate existing docs.
- Update docs only when changes are meaningful.
- Preserve canonical terminology.
- Prefer short operational notes over verbose essays.
- Do not claim features exist unless implemented.
- Do not document speculative plans as completed work.

## Workflow

1. Locate the canonical document before editing.
2. Update the smallest relevant section.
3. Remove stale or duplicated wording when found.
4. Preserve links, headings, and terminology.

## Validation

- Verify the doc matches implemented state.
- Verify terminology is consistent with local instructions and skills.
- Verify no speculative or unrelated content was added.

## Report

- Documents changed.
- Decision or behavior documented.
- Redundancy removed.
- Remaining documentation gaps.

## Forbidden

- Do not create duplicate documentation for the same decision.
- Do not expand scope into unrelated docs.
